## 2. 题目一本体：《Git 衍生文档管理器（.gmd）》（PDF 第 1–4 页，逐字）

### 2.1 Intro

Git 衍生文档管理器（.gmd ）

1. Intro

README、设计说明、接口说明、运维手册等文档常由代码或配置衍生而来, 代码变化后，文档可能不再准确
所以想要一种面向 AI 的、类似 Markdown 的衍生文档格式（后缀 .gmd ）及配套 gmd 命令行工具，让 AI 读到一段衍生内容时能立刻得到三个答案：
• 这段内容还准不准；
• 不准时，是照旧用、由自己判断、还是必须重写；
• 想追问"为什么变了"，能直接看到来源的变化过程，不必自己去翻 Git。

同时，普通 Markdown 阅读体验不应被明显破坏。

### 2.2 核心概念

2. 核心概念

| 概念 | 含义 |
|---|---|
| 源内容 / 衍生内容 | 被引用的代码、配置等仓库文件 / 由其总结转换而来的文档内容 |
| 文档 / 片段（block） | 一个 .gmd 文件 / 其中可独立判断新旧状态的一部分 |
| 引用 | 片段对源内容中一段具体范围的引用 |
| 来源版本 / 活动版本 / 历史版本 | 生成内容时对应的 Git 版本及来源信息 / 当前展示的版本 / 同一片段过去生成的版本 |

代码和 Git 历史是事实来源；文档不能靠修改自身说明信息宣称自己是最新的。

### 2.3 一些建议

3. 一些建议

• 单文件自包含：文档标识、片段划分、版本历史、来源信息、Git 版本与时间全部内嵌于 .gmd ；不依赖旁车文件、索引、数据库或文件名。可生成缓存，删除后仅凭该文件即可完整判断语义。
• 文件名不含任何版本信息：hash、版本号、片段标识、来源路径、生成时间只能来自文件内容。
• 片段级独立：多片段状态互不牵连；历史只追加，不覆盖不删除。
• 基于读取时的真实仓库状态判断，不用陈旧缓存；格式损坏或元数据无法解析必须报错，绝不判为可用。
• 不伪造正式版本：来源存在未提交修改时默认拒绝写入。

### 2.4 三档严重度

4. 三档严重度

工具对每个片段只回答一个问题：记录的这段文字还能不能直接用。三档，对应 AI 三种动作：

| 严重度 | 什么时候出现 | AI 的动作 |
|---|---|---|
| ok | 被引用范围内的源内容没变 | 直接用 |
| warning | 引用范围还在，但范围内的内容变了；还算不算准，取决于含义 | 自己判断：接受或重写 |
| error | 引用目标消失或已被整体重写（文件没了、整段被替换或删除） | 必须重写 |

• warning 是唯一需要 AI 解释的一档。工具不猜："变更点 + 来源当前内容"摆出来，由 AI 判断。
• error 刻意隐藏旧文字：留着它，AI 就会去补丁式修改，而引用目标已经不在了。
• 引用范围内有未提交修改时，判为 warning ，且不允许写回。
• 判断只看被引用的范围：同一文件其它地方的改动不算过期。

### 2.5 难度阶段

5. 难度阶段

阶段 1、2 构成最小可用交付，阶段 3 是本题核心目的，阶段 4 为加分。

| 阶段 | 要完成 | 完成标志 |
|---|---|---|
| 1 读得准 | 单文件多片段多版本格式；按引用范围记录与判断；三档严重度 | 只有被引用范围变化才报警，改无关处仍为 ok |
| 2 查得到 | 片段版本历史；来源提交历史；引用目标消失或被整段重写时判为 error 且不输出旧内容 | 对一个失效引用给出原因与追查入口，AI 无需自己调用 Git |
| 3 改得回（核心） | 冲突视图；草稿文件；提交前后的校验；读取 → 判断 → 重写 → 提交闭环且历史不丢 | AI 无人工干预完成一次从 warning 到新版本写入的全过程 |
| 4 进阶（任选其一以上） | 符号/选区级引用；未提交来源的受控写回；分支合并与祖先判断；变更监听或 Git hook；Agent/MCP 集成；冲突辅助；大文档性能优化 | — |

### 2.6 参考命令行接口

6. 参考命令行接口（不要求完全一致，ai会用就行）

工具命令名必须是 gmd 。无需初始化项目或项目级配置；通过 --repo 或当前目录定位 Git 仓库。

| 命令 | 用途 |
|---|---|
| `gmd read <doc> [--block <id>] [--version <id>] [--json]` | 取正文与严重度；默认冲突视图，可切换为只出正文 |
| `gmd log <doc> [--block <id>] [--path <src>] [--range <a..b>] [--json]` | 片段版本历史 / 来源提交历史 |
| `gmd edit <doc> --block <id> [--json]` | 生成草稿文件并返回其路径 |
| `gmd commit <doc> --block <id> [--input <file\|->] [--allow-dirty] [--json]` | 提交草稿或标准输入，追加新版本 |
