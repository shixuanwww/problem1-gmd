### 模块：输出渲染 `src/render.ts`

**1. 这段在干什么（一句话）**
把判定结果渲染成两种形态 —— 给人/AI 看的**冲突视图**（严重度 + 变更点 + 来源当前内容 + 下一命令建议）与 `--json` 单行结构化输出；并提供 `--plain` 的"只出正文"。

**2. 关键设计决策 + 为什么这么做**

- **默认冲突视图，`--plain` 只出正文，`--json` 给结构。** 三者对应三类消费者：人（看冲突）、AI（要正文）、脚本/`jq`（要结构）。题面"默认冲突视图，可切换为只出正文"直接落成默认 + `--plain`（别名 `--body`），且 `--plain` 与 `--json` 互斥。
- **`error` 档不回显任何旧文字**：`currentSource=null`，渲染时打印"当前内容 已刻意隐藏（引用目标已不在…）"，并**必给追查入口** `gmd log <doc> --path <src>`。这是题面阶段 2 完成标志——"对一个失效引用给出原因与追查入口，AI 无需自己调用 Git"。
- **`warning` 档把"变更点 + 来源当前内容"摆出来、工具不猜**：题面"warning 是唯一需要 AI 解释的一档"。渲染只陈列事实（哪几行变了、现在的源码长什么样），**不加判断性措辞**，把决定权留给 AI。
- **`--json` 单行、字段与契约逐一对齐**：`read → {doc, blocks}`、`log → 数组`、`commit → {block,rev,text_hash,range}`、`edit → {draft_path}`；失败时 `{"error","code"}`，**人类可读文字一律走 stderr**，保证 stdout 永远是"可直接 `JSON.parse` 的干净数据"（下面再给兄弟命令都不行）。
- **`--version` 的历史语义**：本地只存活动版本正文，历史版本渲染为"那次生成的来源与摘要信息"，并显式声明"不承诺还原当年正文"（PLAN §4.7 的取舍）。

**3. 可能被追问的问题 + 要点**

- **Q：为什么 `error` 偏偏不给旧文字？给出来不是更方便 AI 对比吗？**
  A：题面原话——"error 刻意隐藏旧文字：留着它，AI 就会去补丁式修改，而引用目标已经不在了"。既然引用目标消失/被整段重写，正确的动作是**整段重写**；给出旧文字会诱导 AI 打补丁，产出更差的结果。这是一条**有意的行为约束**。
- **Q：`--plain` 与 `--json` 为什么必须互斥？**
  A：语义冲突——一个要"纯正文"、一个要"结构化元数据"。若同时给，stdout 既不是合法 JSON 也不是纯正文，`jq`/`JSON.parse` 会崩。互斥并退出码 1，错误明确。
- **Q：`--plain` 下为什么仍然沿用退出码 3（存在 error 块）？**
  A：正文与退出码解耦：即便只出正文，脚本仍需知道"这文档里有失效引用"。所以 `--plain` 照常探测判定结果只用于决定退出码，不打印冲突视图。
- **Q：`--json` 失败时为什么还要在 stderr 再打印一句人话？**
  A：两条通道服务两类消费者：stdout 给机器（`{"error","code"}`），stderr 给人（`错误：…`）。既不污染 stdout，又让终端用户看得懂。
- **Q：`log --path` 的降级提示放在哪？**
  A：渲染成 `renderLogPath(..., note)` 的一行 `※ …`，例如"range 超出当前文件行数（当前 N 行），已降级为列出该文件全部提交"。让 AI 明确知道"这不是全部历史、而是降级结果"。
